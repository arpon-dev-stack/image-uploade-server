Markdown# Auth & Direct Image Upload Server

A production-ready, TypeScript-based Express authentication and secure file management microservice built on PostgreSQL, Prisma ORM, JWTs, and Cloudinary direct-signed uploads.

This server provides secure authentication flows (signup with OTP verification, login, refresh tokens, password resets) alongside a direct client-to-cloud upload system that keeps file bandwidth off your application server while maintaining zero-trust signature authorization.

---

## 🎨 Features & Architecture

### 🔑 Authentication & Authorization
- **Email & Password Authentication:** Passwords hashed using `bcryptjs` (12 salt rounds).
- **OTP Email Verification:** 6-digit numeric OTPs with 10-minute expiry for registration and password resets.
- **Dual JWT Token Strategy:** Short-lived Access Tokens (15 min) and long-lived Refresh Tokens (7 days) signed using `jose`.
- **User Enumeration Protection:** Generic responses on password reset endpoints to mitigate reconnaissance.
- **Schema Validation:** Strict payload validation across all endpoints using `zod`.

### 📸 Secure Direct Cloudinary Uploads
- **Zero-Server-Bandwidth Strategy:** Clients stream files directly to Cloudinary's REST API using short-lived signatures generated by this server.
- **Signed Parameter Security:** File size limits (5 MB) and allowed file formats (`jpg`, `png`, `webp`) are embedded into the server cryptographic signature—Cloudinary rejects tampered client requests.
- **Rate Limiting:** Rate-limiting middleware on signature generation endpoints prevents DDoS attacks and account exploitation.
- **Database Persistence:** Persists resulting Cloudinary `secure_url` strings to the PostgreSQL database via Prisma.

---

## 🛠️ Tech Stack

- **Runtime & Framework:** Node.js, Express 5, TypeScript
- **Database & ORM:** PostgreSQL, Prisma ORM (Contract-driven configuration via `@prisma/orm-postgres`)
- **Tokens & Security:** `jose` (JWT), `bcryptjs`, `express-rate-limit`
- **Validation:** `zod`
- **Email Delivery:** `nodemailer`
- **Cloud Storage:** `cloudinary` (Direct Signed REST API)

💻 Client Integration Flow (Direct Cloudinary Upload)To execute direct-to-cloud uploads on the frontend (React, Vue, React Native, or Vanilla JS), follow this 3-step pattern:TypeScriptasync function handleAvatarUpload(file: File, userAccessToken: string) {
  // Step 1: Request signed parameters from the Auth Server
  const sigRes = await fetch('http://localhost:5000/api/upload/signature', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${userAccessToken}`,
      'Content-Type': 'application/json',
    },
  });
  
  if (!sigRes.ok) throw new Error('Failed to obtain upload signature');
  const sigData = await sigRes.json();

  // Step 2: Upload file directly to Cloudinary REST API
  const formData = new FormData();
  formData.append('file', file);
  formData.append('api_key', sigData.apiKey);
  formData.append('timestamp', sigData.timestamp.toString());
  formData.append('signature', sigData.signature);
  formData.append('folder', sigData.folder);
  formData.append('allowed_formats', sigData.allowedFormats);
  formData.append('max_file_size', sigData.maxFileSize.toString());

  const cloudRes = await fetch(
    `[https://api.cloudinary.com/v1_1/$](https://api.cloudinary.com/v1_1/$){sigData.cloudName}/image/upload`,
    { method: 'POST', body: formData }
  );

  const cloudData = await cloudRes.json();
  if (!cloudRes.ok) throw new Error(cloudData.error?.message || 'Cloudinary upload failed');

  // Step 3: Send returned URL to backend to persist in PostgreSQL
  const saveRes = await fetch('http://localhost:5000/api/upload/save-url', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${userAccessToken}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      imageUrl: cloudData.secure_url,
      publicId: cloudData.public_id,
    }),
  });

  return await saveRes.json();
}
🔒 Security Best Practices ImplementedAPI Keys Privacy: Cloudinary API_SECRET remains strictly server-side and is never exposed to frontend client builds.Signature Verification: Cloudinary validates every client upload against the server-generated signature hash before saving files.Restricted Payload Scope: File formats and sizes are signed; clients cannot arbitrarily bypass limits to upload large files or non-image assets.Endpoint Protection: Access to signature generation requires a valid JWT Bearer header.
